# FundLok backend dependencies — FULLY PINNED.
#
# Why every version is exact: CI (.github/workflows/ci.yml) and the Cloud Run
# buildpack both install from this file, and both resolve fresh. While these were
# ranges (>=), an upstream release could — and on 2026-08-09 did — turn both CI jobs
# red with no change to a single line of our code. Alembic 1.19.0 began comparing
# CHECK constraints in autogenerate; our constraints live in raw DDL inside the
# migrations and are not declared on the ORM models, so `alembic check` reported all
# 28 of them as removed. That failed the migration-check job directly and the test
# job via tests/ledger/test_migration.py, which shells out to `alembic check`.
#
# HOW TO UPGRADE — never edit a version by hand:
#   python3.11 -m venv /tmp/v && /tmp/v/bin/pip install -U pip
#   grep -v '^<package>==' requirements.txt > /tmp/req.txt
#   /tmp/v/bin/pip install <package>==<new version> -r /tmp/req.txt
#   (run the suite against it, then) /tmp/v/bin/pip freeze > requirements.txt
# Then restore this header and the section comments. Verified green on
# Python 3.11 with PostgreSQL 16: alembic upgrade head, alembic check,
# and pytest -q at 175 passed / 0 failed.
#
# The grep step is not optional: every version here is exact, so passing both
# `<package>==<new>` and this file hands pip two conflicting pins for the same
# package and it exits ResolutionImpossible before resolving anything.
#
# CAPPED ON PURPOSE — read before bumping:
#   alembic  held at 1.18.5. 1.19.0+ fails `alembic check` for the reason above.
#            Lifting the cap needs one of: the 28 CHECK constraints declared on the
#            models, or an include_object filter in alembic/env.py that skips
#            check constraints. Do that first, then bump.
#   cryptography
#            held at 49.0.0 by fastapi-mail 1.6.5, which requires
#            cryptography<50.0.0,>=49.0.0 (1.6.5 is the newest release; every
#            earlier one caps it lower still). Pinning 50.0.0 does not merely
#            warn — it fails the fresh resolve in CI and in the Cloud Run
#            buildpack, so the bump has to wait on upstream.
#            49.0.0 carries CVE-2026-69247 (HIGH): a Bleichenbacher oracle in
#            PKCS#7 EnvelopedData decryption. Not reachable from this codebase —
#            nothing here imports cryptography or touches PKCS#7; it is present
#            only as the python-jose and fastapi-mail backend. The audit step in
#            ci.yml suppresses it by ID. When fastapi-mail lifts the cap, bump to
#            50.0.0 and delete that --ignore-vuln pair.
